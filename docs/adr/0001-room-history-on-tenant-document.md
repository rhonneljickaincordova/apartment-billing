# Room history lives on the tenant document, not a separate collection

When a tenant transfers to a new room, the record is appended to a `roomHistory[]` array on the tenant document rather than written to a dedicated `roomTransfers` Firestore collection. This matches the repo's existing pattern of embedding tenant-scoped history (payments live on `bill.payments`, ID images on `tenant.validIdImages`), keeps the transfer record co-located with the tenant for read-time efficiency (no join across collections when rendering `TenantDetailsModal`), and avoids the overhead of a second collection whose only consumer is the tenant view. Reconsider if cross-tenant analytics on transfers ever become a use case (e.g. "which rooms churn tenants fastest") — that query pattern would benefit from a top-level collection.
